What I need from you

Nothing here blocks a demo — the system runs today with mock payments and console OTPs. This is what turns a working build into a live banking product.

A Hard blocker for production B Scope decision C Before public launch
A1

Razorpay live account

Payments run in mock mode: the full flow works, but no real money moves. Signature verification and idempotency are real, tested code — only keys are missing.

  • Live key ID and key secret
  • A webhook secret you choose, registered against /api/payments/webhook
  • Confirmation of the settlement account
  • Decide: who absorbs the ~2% gateway fee — the bank, or the customer's deposit? It changes the ledger math.
A2

SMS gateway for OTP login

MSG91 and Twilio are both fully implemented — pick one and send credentials. Today OTPs print to the server log.

  • MSG91: auth key, approved 6-character sender ID, and a TRAI DLT registered template
  • Twilio: account SID, auth token, sending number
  • Start the DLT registration first — it is the longest external lead time on this page, and carriers silently drop unregistered transactional SMS
A3

Production database

Runs today on an embedded database — ideal for demos, unsuitable for production. A managed Postgres 14+ connection string switches it over with no code change.

  • Managed Postgres connection string
  • Backup schedule and retention — this is a ledger, so point-in-time recovery matters more than usual
A4

Hosting, domains, and ownership

Self-hosted Docker, a managed platform, or the bank's own infrastructure — all three are documented and supported.

  • Two domains, e.g. api. and admin., plus TLS
  • Who runs operations day to day
  • Needed before the production admin build: the final API domain is compiled into the admin bundle and cannot be changed by editing a config file later
B2

Is there a field agent role?

The build plan has customers paying from their own phones. Most real pigmy schemes have an agent collecting cash door to door. If that is in scope we need an agent role, a collection screen, cash-vs-digital reconciliation and a settlement report. Today there are two roles: village-scoped admin, and superadmin.

B3

Business rules to pin down

  • Minimum and maximum deposit per day, and any per-customer cap
  • Missed-day handling — a reminder fires after 3 days; is there a penalty or only a nudge?
  • Which KYC documents count, and who is authorised to approve them
  • The process when a payment is charged wrongly
  • Audit log retention period — likely 8–10 years, and it drives storage sizing
C1–C5

Before public launch

  • Branding: bank name, logo, app icon, colours — and confirm the Android package name, which is permanent once published
  • Play Store: listing copy, screenshots, and a hosted privacy policy URL (Google rejects financial apps without one)
  • Upload keystore: the signing mechanism is wired and ready. I did not generate the key — whoever holds it controls all future updates, and losing it means the app can never be updated. That custody call is the bank's
  • Hindi copy: the app ships English and Hindi; my Hindi banking terms need a native-speaker review
  • Legal: T&Cs, privacy policy, data-residency rules, and whether InfoSec requires a penetration test — worth scheduling early, as it can gate go-live by weeks
  • Real data: the true village and admin lists, and whether existing paper balances must be imported as opening ledger entries

The one open product decision

B1 Needs your answer before scope can be called complete

Withdrawals, maturity and interest are not built

The system today handles deposits only. There is no way for a customer to withdraw, close an account, or receive maturity proceeds. The ledger already supports debits, so the foundation is there — but no withdrawal flow was in the build plan, so none was built, and I would rather ask than guess at a bank's rules.

  1. Do pigmy accounts have a fixed term? What happens at the end of it?
  2. Is interest paid — at what rate, compounded how? None is calculated today.
  3. Can a customer withdraw early? Full or partial, and is there a penalty?
  4. Where does money go out to — the saved bank account, or cash at the branch?
  5. Who authorises a withdrawal? For a bank I would expect maker-checker approval, which is real work to build properly.

Until this is answered, the product is a collection-only system. That may be exactly right for phase one — I just need it stated, because it is the difference between a finished phase and half a savings product.
